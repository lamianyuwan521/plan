## 0. 一页纸摘要

### 0.1 产品是什么

小一二减肥记是一款**围绕「日」组织的个人减重记录工具**。它不追求复杂的营养学计算，也不做社交和挑战赛，只解决一个核心问题：

> 减肥期间，我每天该吃什么、实际吃了多少、喝了多少水、体重有没有朝目标走？

产品把「体重、食谱、喝水」放进同一张日历：早上称重，白天照着食谱吃并打勾，随手记喝水，晚上看完成度，月底看趋势。

## 1. 产品概述

### 1.1 背景与问题

减重的人通常同时使用多个工具：体重秤 App 记体重、备忘录列食谱、外卖软件看热量、水杯或手环提醒喝水。信息彼此割裂，导致三个问题：

1. **记录成本高**：每件事都要打开不同 App，坚持不了几天。
2. **因果看不见**：不知道自己吃得怎么样、喝得够不够，和体重变化有什么关系。
3. **反馈太苛刻**：多数工具只展示数字和红绿箭头，缺少温和的正向反馈。

小一二减肥记把这三件事收进一个界面，用日历作为「复盘的主视图」，让记录和回顾都变得轻。

### 1.2 产品定位

- **一句话定位**：给自己用的、日历化的减重记录本。
- **产品气质**：温和、清爽、不制造焦虑；像一个靠谱的朋友，而不是严厉的教练。
- **使用频率**：每天 2–4 次，单次 10–60 秒。
- **使用场景**：家中、办公室、通勤途中；离线可用。

### 1.3 目标用户

**主用户（P0）**

- 20–40 岁，希望减重 3–15 kg 的上班族。
- 有一台 iPhone，习惯用手机记录生活。
- 不想学习复杂营养学，只需要「今天该吃什么、吃了多少」。
- 重视隐私，不接受强制注册和云账号。

**次用户（P1）**

- 想帮伴侣 / 家人一起记录的人（V1 不做多账号，仅支持切换单份数据备份）。

### 1.4 核心价值主张

1. **两步记录**：任何一条体重、饮食、喝水记录，最多两步完成。
2. **一处复盘**：日历上同时看到体重、三餐完成度、喝水达标情况。
3. **正向反馈**：只强调「做到了什么」，超预算时给建议，不用红色羞辱。
4. **数据属于自己**：全部数据存在本机，可随时导出、删除。

### 1.5 设计原则

| 原则 | 具体含义 | 落地例子 |
| --- | --- | --- |
| 两步内完成 | 高频操作不超过两次点击 | 首页「+200 ml」直接记喝水；体重页悬浮按钮直接呼出数字键盘 |
| 一屏看到今天 | 今日页回答「今天怎么样」 | 体重、热量环、餐单、喝水四张卡同屏 |
| 只鼓励，不指责 | 超标时给下一步建议 | 「比预算多 120 kcal，晚上散步 20 分钟就差不多啦」 |
| 默认值聪明 | 减少填写负担 | 餐次按时间自动推断；水量目标按体重计算 |
| 离线优先 | 不依赖网络 | 无账号、无请求、首屏即数据 |
| 日历是主视图 | 日维度的所有信息可回溯 | 食谱模块默认展示月历 |

### 1.6 成功标准（个人产品版）

| 指标 | 目标 |
| --- | --- |
| 首次配置完成率 | ≥ 90% |
| 单次记录耗时 | ≤ 30 秒 |
| 7 天内至少记录 5 天 | ≥ 80% |
| 连续使用 30 天 | 自用目标：不中断 |
| 日历日详情打开率 | 每周 ≥ 3 次 |

## 2. 用户与场景

### 2.1 用户画像：「小一二」

- 28 岁，互联网公司职员，身高 163 cm，体重 66 kg，目标 55 kg。
- 工作日久坐，午餐常点外卖，晚上偶尔加班。
- 下载过三款减肥 App，都因为「要填太多」「广告太多」放弃。
- 希望：每天花一分钟记录，周末看一眼就知道这周做得怎么样。
- 担心：数据丢失、App 太啰嗦、体重没降时被「批评」。

### 2.2 关键场景

**场景 A：早晨称重（7:30）**

起床、上完厕所、早餐前称重。打开 App，首页体重卡显示「今天还没记录」，点一下，数字键盘弹出，输入 62.4，保存。首页显示「较昨日 −0.3 kg」，日历上今天出现 62.4。

**场景 B：午餐打卡（12:10）**

打开 App → 食谱 → 日历默认选中今天 → 午餐里已有「鸡胸肉糙米饭 420 kcal」，吃完点勾。热量环从 280 变成 700 kcal，剩余 800 kcal。

**场景 C：下午喝水（15:00）**

收到喝水提醒，点通知打开 App，喝了一杯 300 ml，首页喝水卡点「+300」，进度从 900 变成 1200 / 2000 ml。

**场景 D：晚餐前决策（18:20）**

打开日历看今天：已吃 700 kcal，晚餐计划 430 kcal，合计 1130，预算 1500，还有 370 kcal 余量。决定按计划吃。

**场景 E：周日备餐（20:00）**

打开食谱 → 计划，把下周一到周五的早晚餐排好；「复制上周」把常吃的午餐复制过来，再替换两道。下周每天打开首页就能看到当天该吃什么。

**场景 F：月底复盘（月末周日）**

打开回顾，看到本月体重 −1.8 kg、平均摄入 1460 kcal、食谱完成率 82%、喝水达标 21 天。决定下月把晚餐主食再减一点。

### 2.3 用户旅程

| 阶段 | 用户动作 | 产品支撑 | 关键指标 |
| --- | --- | --- | --- |
| 第 1 天 | 下载 → 填身高体重目标 → 看到预算 | 4 步引导，实时预览每日热量预算 | 引导完成率 |
| 第 1 周 | 每天称重、吃食谱、喝水 | 今日页聚合、内置食谱开箱即用 | 7 日记录 ≥ 5 天 |
| 第 2–4 周 | 形成习惯，开始排下周计划 | 食谱计划、连续打卡、趋势图 | 周计划使用率 |
| 第 2–3 月 | 遇到平台期，需要调整 | 回顾页、趋势对比、目标重设 | 30 日留存 |
| 达成目标 | 切换维持模式 | 目标达成庆祝、预算切维持 | 目标达成率 |

## 3. 名词定义

| 名词 | 定义 |
| --- | --- |
| 体重记录 | 某一天某个时刻的一次体重录入，同一天可以有多条 |
| 代表体重 | 某一天所有体重记录中**时间最晚**的一条，用于日历、趋势和跨日对比 |
| 食谱 | 一道菜或一份餐的模板，包含名称、餐次、热量、食材、做法 |
| 餐次 | 早餐 / 午餐 / 晚餐 / 加餐 |
| 计划餐 | 把某份食谱（或一条快速记录）安排到某天某餐，尚未吃 |
| 已吃餐 | 计划餐被打勾，或通过「快速记录」直接记为已吃 |
| 打卡 | 把一条计划餐标记为「已吃」的动作 |
| 完成度 | 已吃条目数 ÷ 已安排条目数 |
| 热量预算 | 每日建议摄入上限，由 BMR、活动量和减重速度计算 |
| 连续打卡 | 连续若干天每天至少有一条记录（体重 / 饮食 / 喝水） |
| 快速记录 | 不选食谱，直接输入名称和热量记为已吃 |
| 内置食谱 | App 首次启动时预置的食谱，只读，可另存为自己的食谱 |

#### 4.2.3 收起 / 展开交互

- **触发入口**
  - 展开态：侧栏顶部右侧「«」按钮。
  - 收起态：侧栏顶部「»」按钮。
  - 手机：AppBar 左侧汉堡按钮。
  - 桌面端快捷键：`[` 切换展开 / 收起（输入框聚焦时不响应）。
- **动效**：宽度动画 200 ms，`easeOutCubic`；内容区同步平移，不闪烁。
- **状态记忆**：用户最后一次的展开 / 收起状态写入本地设置，下次启动保持；断点变化时按上表重新决定。
- **菜单项**
  - 展开态：图标 + 文字，48 dp 高，圆角 12 dp；选中项使用主题色浅底 + 主题色文字。
  - 收起态：仅图标，居中；鼠标悬停 / 长按显示 Tooltip（今日、食谱、体重、喝水、回顾、设置）。
  - 底部设置与主区分隔线分开，始终可见。
- **内容区**：最大宽度 1200 dp 居中，左右内边距 24 dp；手机 16 dp。
- **无障碍**：每个菜单项提供语义标签「今日，标签页，已选中」；收起态 Tooltip 必须可被读屏读出；焦点顺序自上而下。
- **边界**
  - 窗口从宽变窄时，若当前是展开态且宽度 < 600，自动关闭抽屉，内容不被遮挡。
  - 覆盖式展开时，点击遮罩关闭；按 Esc 关闭。
  - 展开状态变化不触发页面重建，仅布局变化，保留滚动位置。

#### 4.2.4 验收标准

- [ ] 三种宽度下侧栏形态符合上表。
- [ ] 展开 / 收起动画流畅，无内容跳动。
- [ ] 刷新或重启 App 后保持上次状态。
- [ ] 收起态所有图标有 Tooltip，且可键盘聚焦。
- [ ] 手机端抽屉可通过汉堡、遮罩、返回键三种方式关闭。
- [ ] 切换菜单不丢失当前页面滚动位置与未保存表单（表单有未保存提示）。

## 5. 全局交互与视觉规范

### 5.1 布局与间距

- 间距刻度：4 / 8 / 12 / 16 / 24 / 32 dp。
- 卡片圆角 16 dp，按钮圆角 12 dp，标签圆角 999 dp。
- 卡片内边距 16 dp；页面左右 24 dp（手机 16 dp）；卡片间距 16 dp。
- 移动端底部安全区留白；主要按钮不贴底。
- 列表项最小高度 48 dp，可点击区域不小于 44 × 44 pt。

### 5.2 视觉方向

**关键词**：清爽、温暖、食物感、不冰冷。

| Token | 浅色 | 深色 | 用途 |

| Primary Container | `#E3F4EA` | `#1E3A2C` | 选中背景、进度底 |
| Accent | `#F2A65A` 蜜桃橙 | `#F6B87A` | 热量、7 日均线、强调数字 |
| Water | `#5B9BD5` | `#7FB6E6` | 喝水相关 |
| Warning | `#D99A00` | `#E6B23A` | 超预算提示（非错误） |
| Danger | `#D9534F` | `#E5736F` | 仅删除等破坏性操作 |
| Background | `#FBF9F5` | `#121614` | 页面背景 |
| Surface | `#FFFFFF` | `#1C211E` | 卡片 |
| Text Primary | `#1F2A24` | `#ECF1EE` | 正文 |
| Text Secondary | `#6B7A72` | `#A7B3AC` | 辅助信息 |

- 字体：跟随系统（iOS 使用苹方 / SF Pro）；数字（体重、热量、水量）使用等宽数字特性，避免跳动。
- 图标：Material Symbols Rounded 或 Cupertino Icons，线性风格，视觉重量一致。
- 图表配色：体重主色绿、7 日均线橙色虚线、目标线灰色虚线、喝水蓝色、热量橙色。
- 品牌角色「小一二」：一个圆润、简洁的小角色，只出现在空状态、鼓励语和成就弹窗中；不干扰数据阅读，不做拟人化过度设计。
- 深色模式跟随系统，可手动切换；图表颜色在深色下提高明度。

### 5.3 单位与格式

| 项目 | 规则 |
| --- | --- |
| 体重存储 | 一律以 kg 存储，保留 2 位小数 |
| 体重显示 | 公斤：1 位小数（62.4 kg）；斤：1 位小数（124.8 斤），1 斤 = 0.5 kg |
| 单位切换 | 只影响显示，不修改数据；所有输入框标签同步显示单位 |
| 热量 | 整数 kcal，四舍五入；显示为「420 kcal」 |
| 喝水 | 整数 ml；≥1000 时显示为「1.2 L / 2.0 L」 |
| 日期 | 列表内「10月28日 周三」；详情页「2026年10月28日 周三」；存库用 `YYYY-MM-DD` |
| 时间 | 24 小时制「07:32」 |
| 周起始 | 默认周一，可在设置改为周日 |
| 数字空值 | 统一显示「—」，不显示 0 或空白 |
| 负数变化 | 「−0.3 kg」使用减号；下降用绿色，上升用中性灰，不用红色（避免焦虑） |

### 5.4 反馈与确认

- **保存类操作**：立即生效，弹出轻量 Snackbar「已记录 62.4 kg」，3 秒内提供「撤销」。
- **删除类操作**：二次确认弹窗，标题说明影响（例如「删除这条体重记录？」），确认按钮使用 Danger 色。
- **批量 / 不可逆操作**（清空数据、导入覆盖）：输入「删除」二字确认。
- **打卡**：勾选有轻微触觉反馈（移动端）；取消勾选同样提示「已取消」。
- **禁止使用**：整页 loading 遮罩、阻塞式弹窗（除确认类）、超过 3 秒的强制动画。
- **错误提示**：字段级错误显示在输入框下方；系统级错误使用 Snackbar，并提供重试。

### 5.5 空状态 / 加载 / 错误

| 状态 | 呈现 |
| --- | --- |
| 全局无数据 | 今日页显示引导卡「先记录第一次体重吧」+ 主按钮 |
| 某日无食谱 | 日详情各餐显示「还没有安排，去食谱库挑一份」+ 添加按钮 |
| 某日无体重 | 显示「—」+「记录」按钮 |
| 图表无数据 | 显示插画 + 「记录 2 天以上就能看到趋势」 |
| 加载 | 本地数据读取通常 < 100 ms，不显示骨架屏；冷启动显示品牌启动页 |
| 数据库异常 | 页面级错误卡「数据读取失败」+「重试」+「导出数据」 |
| 通知权限被拒 | 设置页提示「已关闭通知，可在系统设置中开启」+ 跳转按钮 |

### 5.6 无障碍

- 支持系统动态字体，最大 2 倍字号不截断关键数字。
- 正文对比度 ≥ 4.5:1，大字号 ≥ 3:1。
- 所有图标按钮提供语义标签；图表提供文字摘要（读屏可读「近 30 天体重从 64.2 降至 62.4」）。
- 不只靠颜色传达状态：完成 / 未完成同时使用图标形状差异。
- 支持减少动态效果（系统开启时缩短动画至 0 ms）。

## 6. 功能需求

### 6.0 首次启动与目标设定

**目标**：90 秒内完成必要配置，并让用户看到「我每天可以吃多少」的结果。

**流程（4 步）**

1. **欢迎页**：品牌名、一句定位、「开始使用」；底部小字「数据只保存在你的手机里」。
2. **基础信息**：
   - 昵称（默认「小一二」，可改）
   - 性别（女 / 男 / 不透露）
   - 出生年份（滚轮，范围 1940–当前年）
   - 身高（cm，100–230，步进 1）
   - 当前体重（kg 或斤，按已选单位；20–300 kg）
3. **目标**：
   - 目标体重（默认当前体重 − 5 kg，可改）
   - 减重速度（0.25 / 0.5 / 0.75 / 1.0 kg 每周，默认 0.5）
   - 实时显示「预计达成日期」
   - 可点「先不定目标」，进入维持模式
4. **活动量 + 结果预览**：
   - 活动量四选一：久坐 / 轻度活动 / 中度活动 / 高度活动
   - 展示计算结果：每日热量预算、喝水目标、BMI
   - 可点击「调整」返回修改
   - 「完成」进入今日页

**规则**

- 必填：昵称、性别、出生年份、身高、当前体重；目标可跳过。
- 所有输入即时校验，未通过时「下一步」置灰并说明原因。
- 引导只在首次启动出现；完成后写入 `onboarding_done`。
- 中途退出保留已填写内容，下次继续。
- 设置页可随时修改全部资料；修改身高 / 体重 / 目标 / 速度 / 活动量后重新计算预算，并提示「预算已更新为 X kcal」。

**验收标准**

- [ ] 首次启动必须进入引导，完成后不再出现。
- [ ] 任一必填项缺失时无法进入下一步。
- [ ] 第 4 步展示的预算、水量、BMI 与第 7 章公式一致。
- [ ] 修改目标或体重后，首页预算同步更新。
- [ ] 选择「先不定目标」后，预算按维持体重计算，首页提示可随时设置目标。

### 6.1 今日（聚合首页）

**目标**：不点击任何菜单，就能回答「今天怎么样、还差什么」。

**页面结构（自上而下）**

1. **顶部栏**：日期 + 星期 + 连续打卡天数（🔥 N 天）；右上角设置入口（手机端）。
2. **体重卡**：
   - 今日代表体重（大数字）；未记录显示「—」。
   - 对比文案：优先对比昨日代表体重；昨日无记录则对比最近一次记录并标注日期。
   - 主按钮「记录体重」，点击呼出底部数字键盘弹层。
3. **热量卡**：
   - 环形进度：已吃 / 预算；中心显示剩余 kcal。
   - 环形上另有一条细刻度表示「今日计划总量」，让用户看到计划是否超预算。
   - 副文案：「已吃 1180 · 计划 1610 · 预算 1500」。
   - 超预算时显示「超出 120 kcal」并使用 Warning 色，附一句温和建议。
   - 点击进入食谱日历的今天。
4. **今日餐单卡**：
   - 四个餐次（早 / 午 / 晚 / 加餐），每条显示名称、热量、勾选框。
   - 勾选即打卡，热量环即时更新。
   - 每餐右侧「+」打开添加弹层；空餐次显示「未安排」。
   - 点击餐次标题进入日详情。
5. **喝水卡**：
   - 进度条 / 小环：1200 / 2000 ml。
   - 「+200」「+300」快捷按钮；点击卡片进入喝水页。
6. **鼓励语**：根据状态显示一句（见 6.1.1）。
7. **快捷操作栏**（悬浮或底部固定）：记体重 / 记饮食 / 喝水。

**规则**

- 数据实时联动：任一模块记录后，今日页、日历、回顾同步刷新。
- 跨零点：App 在前台跨过 00:00 或从后台恢复时，自动切换到新的一天并刷新；不打断正在填写的表单。
- 今日页不提供删除操作，删除在对应模块内完成。
- 首次无数据时，体重卡替换为引导卡，餐单卡显示「去食谱库挑一份」。

**6.1.1 鼓励语文案规则**

| 状态 | 文案示例 |
| --- | --- |
| 今天还没有记录 | 「新的一天，先称个体重开个好头吧。」 |
| 已有记录且未超预算 | 「今天稳稳的，继续保持。」 |
| 已超预算 | 「比预算多了 120 kcal，晚上散步 20 分钟就差不多啦。」 |
| 连续 ≥ 7 天 | 「已经连续记录 7 天，小一二替你骄傲。」 |
| 体重达到新低 | 「新低！62.4 kg，离目标又近了一点。」 |
| 达成目标 | 「目标达成！接下来一起稳稳维持。」 |

文案避免「胖」「失败」「又吃多了」等指责性词汇。

**验收标准**

- [ ] 今日页四张卡数据与各模块一致。
- [ ] 打卡后热量环与剩余数值立即更新。
- [ ] 跨零点自动切换日期。
- [ ] 无数据时有引导，不出现空白页面。
- [ ] 鼓励语与状态匹配，不出现指责性文案。

### 6.2 食谱

**入口**：侧边栏「食谱」。
**默认 Tab**：日历。
**顶部**：标题「食谱」+ 右侧「+ 添加食谱」。
**Tab**：日历 / 食谱库 / 计划（P1，基础版 P0）。

#### 6.2.1 日历

**目标**：用一张月历回答「这个月我每天吃了什么、体重多少、有没有坚持」。

**布局**

- 月份头部：`‹ 2026 年 10 月 ›`，右侧「今天」按钮；点击月份文字可快速选择年月。
- 星期行：一 二 三 四 五 六 日（跟随设置）。
- 月网格：固定 6 行 42 格，非本月日期淡化。
- 单元格内容（高约 72 dp）：
  - 左上：日期数字；今天用主题色圆形底；选中日用描边圆环。
  - 中部：当日代表体重（如 `62.4`）；无记录显示 `—`。
  - 底部：3 个小圆点对应早 / 中 / 晚：
    - 实心绿：该餐有安排且全部完成。
    - 半透明绿 / 空心：有安排但未全部完成。
    - 浅灰：未安排。
  - 右上角：当日喝水达标时显示一个小水滴图标。
- 图例：一行说明「● 已完成 ○ 未完成 · 💧 喝水达标」。
- 左右滑动（移动端）或点击箭头切换月份；滑动方向与月份方向一致。
- 选中日期后，日历下方展示该日详情（见 6.2.2），无需跳页。
- 底部按钮「查看完整日详情」进入 `/day/:date`（P1）。

**规则**

- 无记录日期也正常显示，不隐藏。
- 未来日期：可查看已排计划，但体重显示 `—`，不可记录体重；餐次勾选禁用。
- 日历仅查询当前显示月份的数据，保证滑动流畅。
- 每月最后一天或首日的跨月周正常显示邻月日期。
- 「今天」按钮：跳回当前月并选中今天。
- 月历头部右侧（P1）显示「本月回顾」入口，进入回顾页并定位当月。

**验收标准**

- [ ] 月历正确显示周起始设置、跨月日期、今天与选中态。
- [ ] 单元格同时正确展示体重、三餐完成点、喝水达标水滴。
- [ ] 点日期后下方详情立即更新，不跳页、不闪烁。
- [ ] 未来日期不能记录体重、不能打卡。
- [ ] 切换月份后数据正确、滑动流畅（60 fps）。

#### 6.2.2 日详情（日历下方内嵌 + 完整页）

**目标**：点开某一天，一眼看到体重和早中晚吃了什么、多少热量。

**结构**

1. **日期头**：`10 月 28 日 · 周三`；右侧体重 `62.4 kg`（较上次 −0.3）+「编辑」图标；无记录时显示「记录体重」。
2. **当日汇总条**：
   - 已吃 / 预算 kcal
   - 计划总量 kcal
   - 完成度 `3/4`
   - 喝水 `1200 / 2000 ml`
3. **餐次区块**（顺序固定）：
   - **早餐 / 午餐 / 晚餐 / 加餐**
   - 区块头：餐次名 + 合计热量 + 完成状态（如「2/2 完成」）+「+」按钮。
   - 条目行：勾选框、食谱名（或快速记录名）、份量（可选）、热量、右侧「⋮」菜单（查看详情 / 替换 / 删除）。
   - 空状态：「还没有安排，去食谱库挑一份」+「添加」。
4. **热量小结**：已吃合计、计划合计、预算、剩余；超预算时给出温和提示。
5. **底部操作**：「+ 添加饮食」；P1「复制这一天到…」。

**添加饮食弹层**

两个入口：

- **从食谱库选择**：搜索 + 餐次筛选 + 最近使用；选中后回到日详情并新增一条计划餐。
- **快速记录**：名称（必填）+ 热量（必填）+ 餐次（按时间推断，可改）+ 开关「已吃过」（默认开）。保存后若开启开关则直接为已吃状态。

**餐次时间推断规则**

| 时间 | 默认餐次 |
| --- | --- |
| 05:00–10:29 | 早餐 |
| 10:30–14:29 | 午餐 |
| 14:30–17:29 | 加餐 |
| 17:30–21:59 | 晚餐 |
| 22:00–04:59 | 加餐 |

**规则**

- 同一天同一餐次允许添加多条（例如午餐两道菜），热量累加。
- 同一天允许记录多次体重，日详情按时间倒序列出；**代表体重取最后一条**。
- 点击条目名称进入食谱详情（自定义 / 内置均可查看）；快速记录无详情页。
- 更换食谱：保留原条目位置与餐次，只替换关联食谱与热量，并二次确认。
- 删除条目：确认后移除；若已打卡，热量合计同步减少。
- 未来日期可添加计划餐，但勾选框禁用，提示「还没到这一天」。
- 完整日详情页与内嵌版信息一致，仅增加「当日体重记录列表」和「喝水记录列表」。

**验收标准**

- [ ] 点击日历任意日期，下方显示该日体重、四餐、热量、喝水。
- [ ] 早 / 中 / 晚 / 加餐的顺序、热量合计正确。
- [ ] 从食谱库添加、快速记录两种方式都能成功新增条目。
- [ ] 勾选 / 取消勾选后，该餐合计、当日已吃、日历圆点、今日页同步更新。
- [ ] 未来日期不能打卡。
- [ ] 删除条目后所有统计同步更新。

#### 6.2.3 食谱库

**目标**：让用户 10 秒内找到想吃的，或添加自己的食谱。

**布局**

- 顶部搜索框：按名称、标签搜索（中文子串匹配）。
- 筛选条：
  - 餐次：全部 / 早餐 / 午餐 / 晚餐 / 加餐
  - 标签：全部 / 高蛋白 / 低碳 / 快手 / 清淡 / 素食
  - 排序：最近添加 / 热量从低到高 / 热量从高到低
  - 收藏开关：只看收藏
- 内容：
  - ≥ 600 dp：两列卡片网格。
  - < 600 dp：单列列表。
- 卡片内容：名称、热量（突出）、餐次图标、标签、收藏星标；内置食谱带「内置」小徽标。
- 空结果：「没有找到相关食谱」+「清除筛选」。
- 右下角悬浮「+」按钮（与顶部按钮一致，移动端用悬浮）。

**规则**

- 内置食谱只读，卡片操作只有「查看」「收藏」「另存为我的食谱」。
- 自定义食谱可编辑、删除、收藏。
- 收藏状态本地保存，排序中收藏不置顶（除非开启「只看收藏」）。
- 删除自定义食谱时，如果已被安排到某些日期：提示「该食谱已被 N 天使用，删除后这些记录会保留名称和热量，但无法再查看详情」，确认后删除；关联条目保留快照。
- 列表默认按最近添加倒序。

**验收标准**

- [ ] 搜索、餐次筛选、标签筛选、排序、收藏筛选可组合生效。
- [ ] 内置与自定义食谱有明确区分。
- [ ] 自定义食谱可编辑、删除；内置只能另存。
- [ ] 删除被引用的食谱有影响提示，历史记录不丢失。
- [ ] 空结果有清除筛选入口。

#### 6.2.4 食谱详情

**内容**

- 顶部：名称、餐次徽标、收藏按钮、更多菜单。
- 热量大数字 + 单位 kcal；若有蛋白质 / 碳水 / 脂肪，显示三项小卡（P1）。
- 标签。
- 食材清单：名称、用量、单位、该食材热量（可选）。
- 做法步骤：编号列表，支持多行。
- 底部固定按钮：「加入今日」或「加入计划」。

**加入流程**

1. 点击底部按钮 → 底部弹层。
2. 选择日期（默认今天，可选未来 / 过去）。
3. 选择餐次（默认按食谱餐次；若食谱为「通用」，按当前时间推断）。
4. 可选「已吃过」开关（默认关；过去日期默认开）。
5. 确认 → 写入计划餐，Snackbar「已加入 10 月 28 日 午餐」+「查看」。

**规则**

- 同一天同一餐可重复加入同一食谱（允许吃两份）。
- 内置食谱的「更多」菜单：收藏、另存为我的食谱。
- 自定义食谱的「更多」菜单：编辑、收藏、删除。
- 另存为：复制全部字段，名称默认加「（我的）」后缀，进入编辑页。

**验收标准**

- [ ] 食谱详情完整展示热量、食材、步骤、标签。
- [ ] 加入指定日期 + 餐次后，日详情出现该条目。
- [ ] 「已吃过」开关正确决定条目初始状态。
- [ ] 收藏状态即时更新并反映在食谱库。
- [ ] 内置食谱不可直接编辑 / 删除。

#### 6.2.5 新增 / 编辑食谱

**表单字段**

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 名称 | 是 | 1–30 字；去除首尾空格 |
| 餐次 | 是 | 单选：早餐 / 午餐 / 晚餐 / 加餐 / 通用 |
| 热量 | 是 | 0–3000 kcal 整数；可切换「按食材自动计算」 |
| 食材 | 否 | 名称、用量、单位（g / ml / 个 / 份）、热量 |
| 做法 | 否 | 多行文本步骤，可增删、自动编号 |
| 标签 | 否 | 预设标签多选 + 自定义，最多 5 个 |
| 收藏 | 否 | 开关 |

**交互**

- 热量自动计算：开启后，热量字段只读，值 = 所有食材热量之和；关闭后恢复手动输入。
- 食材行：底部「+ 添加食材」；每行右侧删除；至少保留 0 行。
- 做法行：每条一个多行输入框；「+ 添加一步」；自动编号 1. 2. 3.。
- 保存：
  - 新建 → 返回食谱库并打开新食谱详情。
  - 编辑 → 返回上一页，Snackbar「已保存」。
- 返回时如有未保存修改，弹窗「放弃修改？」。
- 图片：V1 不上传图片，按餐次生成不同底色的占位图与图标；P1 支持相册选图。

**校验**

- 名称空、热量空或超范围时，保存按钮置灰并在字段下提示。
- 食材热量合计超过 3000 时提示「总热量偏高，请确认」但允许保存。

**验收标准**

- [ ] 必填校验正确，错误提示定位到字段。
- [ ] 自动计算开关能正确汇总 / 恢复手动输入。
- [ ] 食材与步骤可增删，保存后完整回显。
- [ ] 未保存返回有确认提示。
- [ ] 新建的食谱立即出现在食谱库并可加入计划。

#### 6.2.6 食谱计划

**目标**：把「明天 / 下周吃什么」提前安排好，减少临时决策。

**布局（P0 基础版）**

- 周切换：`‹ 10月27日 – 11月2日 ›` +「本周」按钮。
- 7 天列表（移动端）/ 7 列看板（≥ 900 dp）：
  - 每天显示日期、星期、三餐 + 加餐条目、合计热量、完成度。
  - 每餐「+」添加；条目可勾选（今天及过去）。
- 周汇总：计划总热量 / 7 天平均、完成率。

**P1 增强**

- 「复制上周」：把上周条目复制到本周空餐次，不覆盖已有条目；提示「已复制 N 条」。
- 「从食谱库批量添加」：多选食谱后逐日分配。
- 拖拽移动条目到其他日期 / 餐次。
- 「生成一周计划」：按热量预算从收藏 / 内置食谱中推荐组合（规则化，非 AI）。
- 月计划视图。

**规则**

- 计划条目与日详情共用同一数据，任何一端修改另一端同步。
- 过去日期可以补记与打卡；未来日期可安排但不能打卡。
- 计划不等于摄入：未打卡条目不计入「已吃」。
- 周起始跟随设置。

**验收标准**

- [ ] 周视图正确显示 7 天计划与完成度。
- [ ] 添加 / 删除 / 勾选条目与日详情同步。
- [ ] 周汇总热量与完成率计算正确。
- [ ] 未来日期条目不可打卡。

#### 6.2.7 打卡规则

- 打卡对象是**单条计划餐**，不是整餐；一餐多条时逐条勾选。
- 勾选后：`status = completed`，记录 `completed_at`，热量计入「已吃」。
- 取消勾选：`status = planned`，从「已吃」扣除。
- 一餐的完成状态：
  - 全部条目已吃 → 已完成（日历圆点实心）。
  - 有安排但未全部完成 → 进行中（半透明）。
  - 无条目 → 未安排（浅灰）。
- 日完成度 = 已吃条目 ÷ 已安排条目；无任何条目时显示「未安排」。
- 日历的 3 个圆点只对应早 / 中 / 晚；加餐不计入圆点，但计入完成度。
- 一键全部打卡（P1）：在日详情提供「全部打勾」，需二次确认。
- 打卡可撤销（取消勾选或 Snackbar 撤销）。
- 未来日期禁止打卡；过去日期允许补打。
- 打卡不影响食谱本身，只影响当日条目。

**验收标准**

- [ ] 单条打卡 / 取消打卡在所有页面同步。
- [ ] 早 / 中 / 晚圆点状态符合规则。
- [ ] 加餐不计入圆点但计入完成度与热量。
- [ ] 未来日期无法打卡。
- [ ] 打卡有触觉 / Snackbar 反馈。

### 6.3 体重

**入口**：侧边栏「体重」。
**页面结构**：顶部统计卡 + Tab「趋势 / 记录」+ 右下「+ 记录体重」。

#### 6.3.1 记录与编辑

**记录弹层字段**

| 字段 | 规则 |
| --- | --- |
| 体重 | 数字键盘；0.1 步进；20–300 kg（斤模式 40–600 斤）；必填 |
| 日期 | 默认今天；可选过去任意日期；未来日期禁用 |
| 时间 | 默认当前时间；可修改 |
| 体脂率 | 可选，3–60%（P1） |
| 备注 | 可选，50 字以内（P1） |

- 同一天允许多条记录，按时间排序；代表体重为最后一条。
- 保存后 Snackbar「已记录 62.4 kg」+「撤销」；撤销即删除该条。
- 编辑：点击记录行进入同一弹层，字段预填；保存后更新 `updated_at`。
- 删除：记录行「⋮」→ 删除 → 二次确认。
- 单位切换后输入框标签与校验范围同步变化，内部仍存 kg。

**验收标准**

- [ ] 可记录今天与过去日期，不能记录未来。
- [ ] 输入范围校验正确，单位切换后范围正确。
- [ ] 保存后所有相关页面同步。
- [ ] 撤销与删除行为正确。
- [ ] 同日多条记录时代表体重取最后一条。

#### 6.3.2 统计卡

四张卡（移动端 2×2）：

| 卡片 | 内容 |
| --- | --- |
| 当前体重 | 最近一条代表体重 + 日期 |
| 累计变化 | 当前 − 初始体重（首次记录或引导填写） |
| 距目标 | 当前 − 目标；未设目标显示「未设置」 |
| BMI | 数值 + 分类（中国成人标准） |

- 点击 BMI 卡展开说明：BMI 公式、分类区间、局限性（不区分肌肉脂肪）。
- 无数据时：当前体重「—」，其余卡片显示引导。

#### 6.3.3 趋势图

- 范围切换：7 天 / 30 天 / 90 天 / 全部（默认 30 天）。
- 图层：
  - 每日代表体重折线（主色）。
  - 7 日移动平均线（橙色虚线，可开关，默认开）。
  - 目标体重水平线（灰色虚线，设置目标后显示）。
  - 初始体重水平线（浅灰虚线，可开关）。
- 交互：点击 / 长按数据点显示浮层「10月28日 · 62.4 kg · 较上次 −0.3」；左右拖动查看。
- 聚合规则：范围跨度 > 180 天时，按周聚合（每周日均值的平均）并标注「周均」；否则按日。
- Y 轴范围：数据最小 / 最大值各留 1 kg 余量，至少跨度 4 kg。
- 无数据 / 单点：显示插画与「记录 2 天以上就能看到趋势」。
- 图表下方文字摘要，供读屏使用。

**验收标准**

- [ ] 四种范围切换正确，默认 30 天。
- [ ] 7 日均线、目标线、初始线开关正确。
- [ ] 点选数据点浮层信息正确。
- [ ] 超长范围按周聚合且标注。
- [ ] 无数据时显示引导而非空白图表。

#### 6.3.4 记录列表

- 按月份分组，组头「2026 年 10 月 · 共 12 条」。
- 行：日期、星期、体重、较上次变化、时间、`⋮`。
- 变化对比：与上一条记录比较（不要求相邻日期），显示间隔天数，如「较 10/26 −0.5」。
- 排序：时间倒序。
- 空状态：「还没有体重记录」+ 记录按钮。
- 支持下拉刷新（本地数据，刷新即重查，主要用于多端调试）。

**验收标准**

- [ ] 分组、排序、变化计算正确。
- [ ] 编辑 / 删除入口可用。
- [ ] 空状态正确。

### 6.4 喝水

**入口**：侧边栏「喝水」。
**页面结构**

1. **目标显示**：`1200 / 2000 ml`，右侧齿轮可改目标。
2. **环形进度**：中心显示百分比与大数字；达标后变为「已达标」+ 小庆祝动画（一次性）。
3. **快捷按钮**：+200 ml / +300 ml / +500 ml；点击立即记录当前时间。
4. **自定义**：输入 50–2000 ml，可选日期与时间（默认当前，未来禁用）。
5. **今日记录列表**：时间 + 水量 + 撤销图标；按时间倒序。
6. **近 7 天柱状图**：每日总量对比目标线；达标日柱体为实色。
7. **连续达标天数**。

**规则**

- 默认目标 = 体重 × 35 ml，四舍五入到 100 ml，限制在 1500–4000 ml；无体重时默认 2000 ml。
- 目标可在本页或设置页修改，修改后立即生效，不改历史数据。
- 单条记录 50–2000 ml；同一天可多条。
- 删除记录：点击撤销图标立即删除并 Snackbar 提供「撤销」（3 秒）。
- 达标庆祝每天只触发一次；再次低于目标后重新达标不再庆祝。
- 未来日期不可记录。
- 当日总量超过 5000 ml 时显示温和提示「今天喝得不少，注意适量」。

**验收标准**

- [ ] 快捷按钮、自定义、撤销均正确。
- [ ] 目标计算与手动修改正确。
- [ ] 达标状态、庆祝、连续天数正确。
- [ ] 近 7 天柱状图与每日总量一致。
- [ ] 未来日期不可记录。

### 6.5 回顾（P1）

**目标**：用一页回答「这个月做得怎么样，下个月调什么」。

**内容**

- 月份切换：`‹ 2026 年 10 月 ›`。
- 六张统计卡：
  - 体重变化（月初代表体重 → 月末代表体重）
  - 平均每日摄入 kcal（按有记录的日期）
  - 食谱完成率（已吃条目 / 已安排条目）
  - 喝水达标天数
  - 记录天数（任意记录）
  - 最长连续打卡
- 体重趋势小图（当月）。
- 每周平均摄入柱状图（4–5 根柱）。
- 喝水达标热力条（每天一格）。
- 文字洞察（规则生成）：
  - 「本月平均摄入 1480 kcal，比上月少 120 kcal。」
  - 「体重下降 1.8 kg，节奏很稳。」
  - 「有 6 天没有记录，建议设一个称重提醒。」
  - 「晚餐完成率 68%，是一周里最容易掉队的一餐。」
- 空月份：「这个月还没有记录」+ 去记录按钮。

**规则**

- 所有指标只统计有数据的日期，避免被空白天拉低。
- 月初 / 月末代表体重缺失时，用当月最近的有效记录并标注。
- 洞察文案最多 3 条，按优先级：体重变化 > 摄入变化 > 完成率短板 > 记录习惯。

**验收标准**

- [ ] 六项指标与底层数据一致。
- [ ] 月份切换正确，空月份有引导。
- [ ] 洞察文案与实际数据匹配，不出现错误归因。

### 6.7 设置与数据管理

**页面结构（分组列表）**

#### 6.7.1 个人资料

- 昵称、性别、出生年份、身高、活动量。
- 修改后重新计算预算与水量目标，保存时提示变化。
- 入口：设置 → 个人资料。

#### 6.7.2 目标与预算

- 目标体重、目标日期、减重速度（0.25 / 0.5 / 0.75 / 1.0 kg/周）。
- 每日热量预算：默认自动计算；可切换「手动设置」并输入 800–4000 kcal。
- 水量目标：自动 / 手动。
- 修改目标体重低于当前体重时，显示预计达成日期；高于等于当前体重时，进入「维持模式」，预算按 TDEE 计算。
- 减重速度超过当前体重 1%/周时，提示「速度偏快，建议 0.5 kg/周」，但允许保存（需确认）。

#### 6.7.3 偏好

- 体重单位：公斤 / 斤。
- 水量单位：ml / L（仅显示，不影响存储）。
- 周起始日：周一 / 周日。
- 主题：跟随系统 / 浅色 / 深色。
- 启动页：今日 / 食谱。
- 语言：简体中文（V1 唯一）。

#### 6.7.4 提醒（P1）

- 称重提醒：开关 + 时间（默认 07:30）。
- 喝水提醒：开关 + 间隔（60 / 90 / 120 / 180 分钟）+ 活跃时段（默认 08:00–21:00）。
- 用餐提醒：开关 + 三个时间（默认 08:00 / 12:00 / 18:30）。
- 权限申请：首次开启时说明用途；被拒绝时提供跳转系统设置。
- 提醒为本地通知，不依赖网络。

#### 6.7.5 数据

- **导出备份（JSON）**：包含全部表与版本号；通过系统分享 / 下载保存。
- **导出 CSV**：体重、饮食、喝水三个文件；用于表格分析。
- **导入备份（JSON）**：校验版本与结构；选择「合并」或「替换」。
  - 合并：按 id 去重，`updated_at` 较新者胜；完成后展示新增 / 更新 / 跳过条数。
  - 替换：二次确认后清空现有业务数据再导入。
- **清空业务数据**：删除体重、饮食、喝水、成就；保留个人资料与设置；输入「删除」确认。
- **恢复出厂设置**：删除全部数据与设置，回到引导页；输入「删除」确认。
- **上次备份提醒**：超过 30 天未导出时，在设置页显示一行提示（P1）。

## 7. 核心计算规则

### 7.1 年龄与 BMI

- 年龄 = 当前年份 − 出生年份（引导只收集年份，允许 ±1 岁误差）。
- BMI = 体重(kg) ÷ 身高(m)²，保留 1 位小数。

**中国成人 BMI 分类**

| BMI | 分类 |
| --- | --- |
| < 18.5 | 偏瘦 |
| 18.5–23.9 | 正常 |
| 24.0–27.9 | 超重 |
| ≥ 28.0 | 肥胖 |

### 7.2 基础代谢率（BMR）

采用 Mifflin-St Jeor 公式：

```
男性：BMR = 10 × 体重(kg) + 6.25 × 身高(cm) − 5 × 年龄 + 5
女性：BMR = 10 × 体重(kg) + 6.25 × 身高(cm) − 5 × 年龄 − 161
不透露：取男女结果的平均值（即常数项 −78）
```

- 体重取「最近 7 天内最新一条体重记录」；无记录时取引导填写的初始体重。
- 结果四舍五入到整数 kcal。

### 7.3 每日总消耗（TDEE）

```
TDEE = BMR × 活动系数
```

| 活动量 | 系数 | 说明 |
| --- | --- | --- |
| 久坐 | 1.2 | 办公室工作，几乎不运动 |
| 轻度活动 | 1.375 | 每周 1–3 次轻运动 |
| 中度活动 | 1.55 | 每周 3–5 次运动 |
| 高度活动 | 1.725 | 每周 6–7 次运动或体力工作 |

### 7.4 每日热量预算

```
每日缺口 = 每周减重(kg) × 7700 ÷ 7
预算 = TDEE − 每日缺口
```

**健康下限**

- 女性不低于 1200 kcal，男性不低于 1500 kcal，不透露不低于 1350 kcal。
- 同时不低于 `BMR × 1.1`。
- 若触发下限，取两者较大值，并在设置页显示「已按健康下限调整」。

**其他规则**

- 预算四舍五入到 10 kcal。
- 目标体重 ≥ 当前体重时进入维持模式：预算 = TDEE。
- 预算默认按最近体重每日首次打开时重算；用户手动设置后不再自动重算，直到关闭手动模式。
- 修改任一基础资料后立即重算并提示。

### 7.5 减重速度与目标日期

```
预计达成日期 = 今天 + ⌈(当前体重 − 目标体重) ÷ 每周速度 × 7⌉ 天
```

- 速度选项：0.25 / 0.5 / 0.75 / 1.0 kg 每周，默认 0.5。
- 安全提示：每周减重超过当前体重的 1% 时提示速度偏快；超过 1.5% 时强提示。
- 当前体重 ≤ 目标体重时显示「已达成」。

### 7.6 喝水目标

```
目标 = 体重(kg) × 35 ml，四舍五入到 100 ml，限制在 1500–4000 ml
无体重数据时默认 2000 ml
```

用户可手动覆盖；手动值限制 500–6000 ml。

### 7.7 代表体重与变化

- 代表体重 = 某日所有记录中 `recorded_at` 最晚的一条。
- 今日卡片的对比：
  1. 若昨日有代表体重，显示「较昨日」。
  2. 否则显示「较 10/26」并标注日期。
  3. 无任何历史记录时不显示对比。
- 记录列表的变化：与上一条记录比较，并显示间隔天数。
- 体重下降使用绿色，上升使用中性灰；不使用红色。

### 7.8 7 日移动平均

- 对某日 D，取 D 及之前 6 天内所有有代表体重的日期，求平均。
- 至少 2 个有效数据点才绘制，否则该日不显示均线点。
- 结果保留 1 位小数。

### 7.9 完成度与连续打卡

- 条目完成度 = 已吃条目 ÷ 已安排条目（含加餐）。
- 餐次状态：
  - 无条目 → 未安排。
  - 有条目且全部已吃 → 完成。
  - 其他 → 进行中。
- 日完成度 = 当日已吃条目 ÷ 当日已安排条目；无条目显示「未安排」。
- 连续打卡天数：从今天往前，连续每天至少有一条记录（体重 / 饮食 / 喝水）；若今天暂无记录，则从昨天往前计算，今天记录后自动 +1。
- 完成率与连续天数均为派生数据，不落库。

### 8.3 存储与迁移

- 数据库：SQLite（推荐 Drift），单文件存于应用文档目录。
- 偏好设置：`shared_preferences`（主题、侧栏状态、启动页等），或统一放 `profiles`。
- 时间：`date` 存本地日期字符串，`recorded_at` 存 UTC ISO-8601，避免跨时区 / 跨日歧义。
- 迁移：`schema_version` 递增；每次升级提供显式 migration，禁止直接 drop 表。
- 数据量预估：每天 1 条体重 + 4 条饮食 + 5 条喝水，10 年约 3.6 万行，SQLite 占用 < 20 MB。
- 备份：导出 JSON 包含全部表与 `schema_version`；导入时先校验版本，再执行迁移或拒绝。

## 10. 状态与异常清单

| 场景 | 预期行为 |
| --- | --- |
| 首次启动、无任何数据 | 今日页显示引导卡；日历全为「—」；图表显示引导 |
| 设置目标后再修改体重 | 预算、预计日期、距目标同步更新 |
| 目标体重 ≥ 当前体重 | 进入维持模式，预算 = TDEE，文案「维持体重」 |
| 减重速度过快 | 提示并建议 0.5 kg/周；确认后可保存 |
| 同一天多次记录体重 | 全部保留，代表体重取最后一条；列表按时间倒序 |
| 未来日期记录体重 | 禁止，日期选择器不可选未来 |
| 未来日期打卡 | 勾选框禁用，提示「还没到这一天」 |
| 删除正在被计划引用的食谱 | 二次确认；历史条目保留名称与热量快照，详情页提示「食谱已删除」 |
| 食谱被编辑后 | 已存在的条目不变（快照）；之后的条目使用新热量 |
| 跨零点 | 首页自动切到新一天；表单不打断 |
| 单位切换 | 只改显示；输入校验范围同步；不写库 |
| 图表只有 1 个点 | 显示点 + 提示「再记录 1 天就能看到趋势」 |
| 图表跨度 > 180 天 | 按周聚合，标注「周均」 |
| 热量超预算 | Warning 色提示 + 建议，不阻止继续记录 |
| 喝水超 5000 ml | 温和提示，不阻止 |
| 通知权限被拒 | 设置页提示，提供系统设置跳转 |
| 数据库读取失败 | 页面级错误卡 + 重试 + 导出数据 |
| 导入文件格式错误 | 明确提示「文件格式不支持或已损坏」，不做任何修改 |
| 导入版本过低 | 先迁移再导入；失败则拒绝并保留原数据 |
| 导出时无数据 | 允许导出空结构，提示「当前没有可导出的记录」 |
| 应用被卸载 / 重签 | 数据随应用删除；设置页提示定期导出备份 |

## 11. 非功能需求

### 11.1 性能

- 冷启动到可交互 < 3 秒（中端 iPhone），热启动 < 1 秒。
- 首页、日历、趋势页滚动稳定 60 fps。
- 月历查询 < 16 ms；30 天趋势查询 < 50 ms；万级数据量下不卡顿。
- 图表重绘不触发整页重建。
- 安装包体积目标 < 40 MB（不含图片资源）。

### 11.2 可靠性

- 所有写操作在事务中完成；失败时回滚并提示。
- 每日首次打开自动检查数据库完整性；异常时提供导出与修复。
- 跨零点、时区变化、系统时间被修改时不产生错误日期数据。
- 导出文件包含版本号，可被后续版本导入。

### 11.3 隐私与安全

- 无账号、无网络请求、无第三方统计 SDK。
- 数据仅存本机应用沙盒；不使用 iCloud / 相册（V1 无图片）。
- 导出文件由用户主动触发，不自动上传。
- 提供「清空数据」「恢复出厂」；删除即物理删除。
- 隐私说明在设置页与引导页可见。

### 11.4 兼容性

- iOS 15+；Android 8+（若后续构建）；Web 用于预览。
- 屏幕：320 dp 宽到 1440 dp 宽；横竖屏均可用。
- 深色 / 浅色模式；动态字体；减少动态效果。
- 免费签名侧载场景：本地功能完整；不使用推送、iCloud、HealthKit。

### 11.5 可维护性

- 计算逻辑（BMR、预算、均线、完成度）独立为纯函数，带单元测试。
- 数据访问通过 Repository / DAO，UI 不直接写 SQL。
- 文案集中管理，为后续多语言预留 `intl`。
- 主题 token 集中定义，禁止页面内散落硬编码颜色。

### 11.6 测试

- 单元测试：所有计算规则、单位换算、日期边界、连续天数、完成度。
- Widget 测试：引导流程、侧栏收起 / 展开、打卡联动、喝水快捷记录、空状态。
- 集成测试：首次启动 → 记录体重 → 添加食谱 → 打卡 → 日历查看 → 导出。
- 手工验收：iOS 真机（侧载）、Chrome、窄屏 / 宽屏。

### 14.3 关键实现要点

- **侧栏**：`LayoutBuilder` + 断点常量；`AnimatedContainer` 控制宽度；手机用 `Drawer`；状态写入 `shared_preferences`。页面用 `IndexedStack` 或 `ShellRoute` 保持状态。
- **日历**：按月一次性查询 `weight_records`、`meal_entries`、`water_logs`，在内存中聚合成 `Map<date, DaySummary>`，避免 42 次查询。
- **打卡联动**：单一数据源（Drift watch / Riverpod StreamProvider），各页面订阅，避免手动同步。
- **计算器**：全部纯函数，输入基础资料与记录，输出预算、均线、完成度；便于单测。
- **单位**：显示层统一通过 `WeightFormatter` 转换，数据库永远 kg。
- **导入导出**：JSON schema 带 `schema_version`；导入前校验并迁移；合并按 `updated_at`。
- **性能**：图表数据下采样；长列表使用 `ListView.builder`；避免在 `build` 中做查询。

### 14.5 V1.0 实现说明

实际实现与上面的建议存在少量差异，均以“更快交付、跨 iOS/Web 一致”为取舍：

- **状态管理**：使用 `provider` + `ChangeNotifier`（单一 `AppRepository`），未引入 Riverpod。
- **路由**：使用 `IndexedStack` + `Navigator.push` 的单 Shell 结构，未引入 go_router。
- **本地存储**：使用 `shared_preferences` 保存 JSON 文档（profile、weights、recipes、meals、water 五个 key）。表结构仍按第 8 章设计；个人数据量小，iOS 与 Web 行为一致。后续数据量增大时可迁移到 Drift/SQLite，迁移时读取 JSON 并写入数据库即可。
- **导出**：iOS/桌面使用 `file_saver` 的系统保存面板；Web 使用 `package:web` 触发浏览器下载。
- **图表**：体重趋势使用 `fl_chart`；日历、进度环、近 7 天柱状图为自绘组件。
- **主题与品牌**：薄荷绿 + 蜜桃橙，Material 3；应用图标与启动图已生成替换。

## 15. 风险与开放问题

### 15.1 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 热量估算不准确 | 用户对预算失去信任 | 所有热量标注「估算」，允许手动修改；内置食谱标注参考值 |
| 记录疲劳 | 用几天就放弃 | 两步记录、今日聚合、计划复用、温和反馈 |
| 免费签名 7 天过期 | App 闪退、体验中断 | 设置页提示定期导出；文档说明 AltStore 自动续签 |
| 数据丢失（卸载 / 重签） | 历史记录不可恢复 | 导出备份；P1 增加「30 天未备份」提醒 |
| 范围膨胀 | V1 延期 | 严守 P0 清单，P1/P2 不进 V1 |
| 中式饮食热量差异大 | 预算偏差 | 用户可自建食谱、手动改热量；不追求精确到克 |
| 斤 / 公斤混用 | 数据误解 | 全局单位标识；输入框与图表始终带单位 |
| 深色模式图表对比度 | 可读性差 | 图表颜色单独定义深色值；对比度检查 |

### 15.2 待确认问题（附默认决策）

| 问题 | 默认决策 |
| --- | --- |
| 体重默认单位用公斤还是斤？ | 默认公斤，可在设置切换为斤 |
| 是否需要记录体脂 / 围度？ | V1 只做体重；体脂 P1，围度暂不做 |
| 是否需要多用户 / 家庭共享？ | V1 单用户；V2 再评估 |

| 启动页默认今日还是食谱？ | 今日，可在设置改为食谱 |
| 是否接入 Apple Health？ | V1 不接入；免费签名场景优先本地 |
